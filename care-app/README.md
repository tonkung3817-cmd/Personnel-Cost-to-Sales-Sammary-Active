# ศูนย์ดูแลพนักงานสาขา (Care App)

เว็บสำหรับเก็บข้อมูลที่พักพนักงาน รับแจ้งประสบภัย และให้ผู้ดูแลวางแผนช่วยเหลือ โดยใช้พิกัดสาขาเป็นจุดศูนย์กลาง

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` + `employee.js` | หน้าพนักงาน: แบบสำรวจที่พัก, แจ้งประสบภัย, ปุ่ม "ใช้ตำแหน่งปัจจุบัน", คลิกแผนที่ปักหมุด |
| `admin.html` + `admin.js` | หน้าผู้ดูแล: ภาพรวม, สาขาเป็นศูนย์กลาง, พนักงาน (เห็นพิกัด), ภัยพิบัติ, ประเมินผลกระทบ, ตั้งค่า |
| `common.js`, `style.css` | ส่วนที่ใช้ร่วมกัน |
| `config.js` | **แก้ค่า Supabase ที่นี่** |
| `supabase/schema.sql` | ตารางและสิทธิ์ระดับแถว (RLS) |

เป็นไฟล์ static ล้วน ไม่ต้อง build นำโฟลเดอร์นี้ไปวางบนเว็บเซิร์ฟเวอร์ภายในได้เลย

## ขั้นตอนติดตั้ง (สำหรับทีม IT)

1. **สร้างโปรเจกต์ Supabase** (หรือ self-host) แล้ววาง `supabase/schema.sql` ใน SQL Editor แล้ว Run
2. **ตั้งค่า Auth** (Authentication > Providers > Email)
   - เปิด Email, ใช้การล็อกอินด้วยรหัส OTP: แก้ template "Magic Link"/"Confirm signup" ให้แสดง `{{ .Token }}` (รหัส 6 หลัก)
   - ตั้ง SMTP ขององค์กรเพื่อส่งอีเมล
   - จำกัดโดเมนอีเมลบริษัท (แนะนำให้บังคับที่ฝั่ง Supabase ด้วย เช่น Auth Hook) และใส่ค่า `ALLOWED_EMAIL_DOMAIN` ใน `config.js`
3. **ใส่ค่าใน `config.js`**: `SUPABASE_URL` และ `SUPABASE_ANON_KEY` (ห้ามใส่ service_role key เด็ดขาด)
4. **โฮสต์บน https** (จำเป็น เพราะปุ่ม "ใช้ตำแหน่งปัจจุบัน" ทำงานได้เฉพาะ https) ตั้งค่า Site URL / Redirect ใน Supabase ให้ตรงกับโดเมน
5. **สร้างผู้ดูแลคนแรก**: ให้ผู้ดูแลเข้า `admin.html` ล็อกอินหนึ่งครั้ง แล้วรัน SQL ท้ายไฟล์ `schema.sql` (แก้อีเมล)
6. เข้า `admin.html` > ตั้งค่า > **นำเข้าไฟล์สาขา (.xlsx)** (คอลัมน์: Location, Description, Description (THA), Region, Regional, Province (TH), Lat/Long)
7. ส่งลิงก์ `index.html` ให้พนักงาน

> ไฟล์สาขาและข้อมูลพนักงานไม่ถูกเก็บในโค้ด/Git ทุกอย่างอยู่ในฐานข้อมูลเท่านั้น

## สิทธิ์ (บังคับที่ฐานข้อมูล)

- **พนักงาน**: เขียน/อ่านได้เฉพาะข้อมูลของตัวเอง
- **ผู้ดูแลระดับสาขา** (`role = 'branch'`): เห็นเฉพาะสาขาที่กำหนดใน `branch_ids`
- **ผู้ดูแลระดับภาค** (`role = 'region'`): เห็นเฉพาะสาขาในภาคที่กำหนดใน `regional` (ตรงกับคอลัมน์ Regional)
- **admin**: เห็นทั้งหมด จัดการสาขา ตัวเลือก และข้อมูลจำลอง

ตัวอย่างการเพิ่มผู้ดูแล อยู่ท้ายไฟล์ `schema.sql`

## PDPA

ข้อมูลที่อยู่และพิกัดบ้านเป็นข้อมูลส่วนบุคคล ควรกำหนดฐานทางกฎหมาย/ระยะเวลาเก็บ และจำกัดผู้ที่ได้รับสิทธิ์ผู้ดูแลให้น้อยที่สุด หน้าจอมีช่องยินยอมให้พนักงานติ๊กก่อนส่งข้อมูล

## ทดสอบ

ทดสอบกับ Supabase จำลองในหน่วยความจำ (ล็อกอิน, บันทึกแบบสำรวจ, แจ้งภัย, ปุ่มตำแหน่งปัจจุบัน, มุมมองสาขาศูนย์กลาง, บันทึกสถานะ) ยังไม่ได้ทดสอบกับ Supabase จริงและนโยบาย RLS ใน `schema.sql` ควรทดสอบบนโปรเจกต์จริงก่อนเปิดใช้งาน เช่น ล็อกอินด้วยบัญชีพนักงานแล้วตรวจว่าอ่านข้อมูลคนอื่นไม่ได้
